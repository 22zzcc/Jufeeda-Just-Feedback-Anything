# Mission · JUST FEEDBACK ANYTHING

一个住在终端里的**成长教练**。它不是"挑毛病的工具"，而是一个**记得你、催着你、陪你变强**的长期伙伴。

## 一句话定位

> **反馈不是挑刺，是陪你变强的教练。**

## 三支柱

| 支柱 | 含义 | 落地 |
| :--- | :--- | :--- |
| ① 督促力（教练） | 不是一次性体检，而是持续跟进：反馈 → 盯行动 → 复检 → 完成 | `nudge` 督促、`acceptance` 验收标准 |
| ② 记忆力（档案） | 把反馈、badcase、你做过的事沉淀成个人档案，越用越懂你 | `store` 记录任何事、badcase 落库 |
| ③ 陪伴感（终端伙伴） | 轻量、命令行、随叫随到，长期陪伴而非用完即弃 | `main.py` 全命令行 |

## 能做什么

1. **反馈任何事**：PRD / feature spec / roadmap / 简历 / 报告 / 代码 diff——输出结构化反馈（问题/严重程度/位置/建议/验收）。
2. **记录任何事**：代码反馈、产品迭代、目标、待办——`add` 记录、`done` 完成。
3. **督促完成**：`nudge` 用教练语气催你把没做完的事做完。
4. **集成 SDD 开发能力**：反馈每条带验收标准（SDD validation 精髓）；本项目的开发本身走 SDD（见 `specs/`）。
5. **集成 badcase / 收集信息**：把反馈和你的行为沉淀成成长档案（badcase 复用，越用越准）。

## 成功标准（可判真假）

- 对任意文本，离线 1 秒内输出 ≥3 类结构化反馈，每条带「建议 + 验收标准」；
- 能记录并督促任意待办，`add → nudge → done` 形成闭环；
- 缺失必要章节能被标记为 error。

## 边界（不做什么）

- 不自动修复内容（只反馈、不改）；
- 不做多文件目录递归评审（Backlog）；
- 不做领域硬编码规则（reviewer 可插拔）。
