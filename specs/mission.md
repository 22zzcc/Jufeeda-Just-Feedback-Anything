# Mission

一个**可复用的反馈 harness**：给它「任何事」（PRD / feature spec / roadmap / 简历 / 报告 / 代码 diff……），它输出结构化反馈——问题、严重程度、位置、改进建议、验收标准。

- **要解决什么问题**：评审这件事高度重复（检查完整性、可验证性、清晰度、可执行性），却总靠人肉逐条看，容易漏、口径不一。
- **目标用户**：写 spec / PRD / 文档的人、code review 的协作者、想快速给一份材料「挑毛病」的人。
- **关键利益相关方**：作者（要 actionable 的建议）、审阅者（要统一口径、省时间）。
- **约束与边界**：不做自动修复（只反馈、不改内容）；不做领域专用的硬编码规则（可插拔 reviewer）。
- **成功标准（可判真假）**：对任意文本输入，能在 1 秒内（离线规则模式）输出 ≥3 类结构化反馈，且每条反馈带「改进建议 + 验收标准」；缺失必要章节能被标记为 error。
